# CP-08-105 — per-workspace single-writer cutover discovery

- **Package:** 101 — Per-workspace single-writer cutover (PR 1)
- **Status:** accepted — `efecnc/altai-app-1` PR #80
- **Depends on:** 053, 060 and 100

Inventory every path that can authoritatively mutate workspace state today
— desktop commands, CLI serve, scheduler, importers, legacy frontend
stores — and define the cutover plan that leaves exactly one writer per
workspace with feature-flag-selected ownership: per writer, what it
mutates, whether it routes through the protocol dispatcher, which canonical
counterpart must exist before it loses authority, and the ordered sequence
in which authority transfers without any window holding two writers. No
second scheduler may appear during migration.

**Outcome:** `SINGLE_WRITER_CUTOVER_DISCOVERY.md` records that the gate is
violated by design today (two table families with live writers in one
`work.db`; a read-only dispatcher every mutation bypasses; no cross-binary
arbitration), inventories ten writer classes, and stages the cutover:
slice A primitives (flock inside `WorkStore::open` — the only point every
M1-family writer passes through, including one-shot CLI commands — plus a
flag ledger and acceptance matrix), slice B dispatcher mutation surface,
slice C per-domain authority transfers. Drafted from a deep grounding
report with every contested anchor re-verified directly; an independent
adversarial review's findings (1 CRITICAL enforcement-point correction,
4 MAJOR) were applied before submission.
