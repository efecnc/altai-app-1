## Resolved design decisions (reviewer-facing rationale)

- **D1 — Snapshot target.** Each Cron-schedule automation becomes a
  canonical WorkItem (title/description carry the automation's message)
  plus a Routine/RoutineRevision `Recurring{cron_expression}` targeting
  it, plus a v6 mapping row holding verbatim provenance. At/Every
  schedules are not expressible in canonical vocabulary; their rows get
  disposition `incompatible` and the enable refuses naming them — the
  workspace stays legacy until the automations are removed or the
  trigger vocabulary grows (recorded reopener; never silent loss, never
  dual-run, protocol stays pure).
- **D2 — Ownership + arbitration.** New ledger keys `schedule_owner`
  (`desktop_host` | `daemon`). Authority = flags say this process AND it
  holds the workspace lock. The desktop already holds the app-run lock
  (CP-08-106); a daemon named owner acquires the same lock and fails
  typed-closed (`WorkspaceHeld`) against a live desktop — the kernel,
  not convention, enforces single-writer.
- **D3 — Cross-database atomicity.** Enforcement lives in the fire-time
  gate (desktop_host checks the flags before firing), not in retirement
  bookkeeping: crash after flip before retire suppresses anyway. Crash
  during snapshot is safe by idempotent re-run (deterministic ids from
  automation id + content hash). Flip order: snapshot → verify → set
  flags → mark retired.
- **D4 — Flag timing.** Ledger is read every tick/iteration (60 s bridge,
  driver tick, renderer surface read at session start); flips apply at
  tick boundaries.
- **D5 — legacy_cron_compatibility.** It is the rollback switch: set true
  and authority reverts to legacy wholesale (canonical driver idles,
  CronActor fire gate lifts). Exactly one authority at any instant by
  construction, invariant 6 intact.
- **D6 — Claimed wakes.** Recorded with lease; no run starts (existing
  execution adapter is out of scope).
- **D7 — Renderer flag access.** One new read-only Tauri command in
  `control_plane_flags.rs` exposing the resolved scheduling-authority
  state to the frontend.

## Required negative tests

- Flag absent → all legacy paths behave exactly as today.
- Flag-on + both processes alive → exactly one tick source drives; the
  other is idle (bridge ledger check + daemon WorkspaceHeld refusal).
- Enable while an automation is unmapped or At/Every → typed refusal
  naming it; flag still off; legacy intact.
- Snapshot re-run after interruption → same mappings, zero duplicates.
- Flag-on → agent automation create fails typed-closed.
- Flag-on → renderer reconcile issues no claim/dispatch.
- Blocked wake under the driver stays unclaimed.

## Compatibility and deletion effects

- Flag-off default: every existing caller unaffected; all new behavior
  sits behind the ledger.
- CronActor and its tool surface are gated, not deleted; standalone
  Local/MultiTenantEdge scheduling modes untouched; deletion is package
  102.
- The daemon binary grows a ledger dependency; flag-free deployments see
  no change.
