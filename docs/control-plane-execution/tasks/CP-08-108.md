## Resolved design decisions (reviewer-facing rationale)

- **D1 — Snapshot target.** Each Cron-schedule automation becomes a
  canonical WorkItem (title/description carry the automation's message)
  plus a Routine/RoutineRevision `Recurring{cron_expression}` targeting
  it, plus a v6 mapping row holding verbatim provenance. At/Every
  schedules are not expressible in canonical vocabulary; their rows get
  disposition `incompatible` and the enable refuses naming them — the
  workspace stays legacy until the automations are removed or the
  trigger vocabulary grows (recorded reopener; never silent loss, never
  dual-run, protocol stays pure).
- **D2 — Ownership + arbitration.** New ledger keys `schedule_owner`
  (`desktop_host` | `daemon`). Authority = flags say this process AND it
  holds the workspace lock. The desktop already holds the app-run lock
  (CP-08-106); a daemon named owner acquires the same lock and fails
  typed-closed (`WorkspaceHeld`) against a live desktop — the kernel,
  not convention, enforces single-writer.
- **D3 — Cross-database atomicity.** Enforcement lives in the fire-time
  gate (desktop_host checks the flags before firing), not in retirement
  bookkeeping: crash after flip before retire suppresses anyway. Crash
  during snapshot is safe by idempotent re-run (deterministic ids from
  automation id + content hash). Flip order: snapshot → verify → set
  flags → mark retired.
- **D4 — Flag timing.** Ledger is read every tick/iteration (60 s bridge,
  driver tick, renderer surface read at session start); flips apply at
  tick boundaries.
- **D5 — legacy_cron_compatibility.** It is the rollback switch: set true
  and authority reverts to legacy wholesale (canonical driver idles,
  CronActor fire gate lifts). Exactly one authority at any instant by
  construction, invariant 6 intact.
- **D6 — Claimed wakes.** Recorded with lease; no run starts (existing
  execution adapter is out of scope).
- **D7 — Renderer flag access.** One new read-only Tauri command in
  `control_plane_flags.rs` exposing the resolved scheduling-authority
  state to the frontend.

## Review-fix record (adversarial reviews, both CHANGES-REQUESTED)

Two independent adversarial reviews of the implementation returned
CHANGES-REQUESTED (TS/renderer: 2 HIGH, 2 MEDIUM, 2 LOW; Rust/backend:
1 CRITICAL, 5 HIGH, 3 MEDIUM, 3 LOW; invariants 1, 2, 3, 4, 6 FAIL,
5, 7 PASS). All findings were resolved in-scope (CP-08-106/107
precedent); the `allowed_files` list above was amended to the full
touched set (declaration fix, no unrequested edits).

- **F1 (CRITICAL) — flag-off idled the daemon bridge forever.**
  `ScheduleAuthority::canonical_decided()` separates "the ledger has
  decided" from "the ledger named this process"
  (scheduler_driver.rs). `RoutineCronBridge::gated_tick` now has three
  paths: undecided/rolled-back → unconditional legacy tick with the
  workspace lock never taken (byte-for-byte the pre-cutover daemon);
  decided + owner==daemon → hold the lock and drive; decided + owned
  elsewhere → idle and release. Restores acceptance criterion 1
  (flag-off = byte-for-byte today). Tests: undecided materializes
  without the lock; legacy-rollback materializes; desktop ownership
  idles + releases; a held workspace keeps the bridge idle until
  release.
- **F2 (HIGH) — LegacySchedule serde shape.** The transfer's schedule
  type was externally-tagged lowercase; pinned isanagent serializes
  `#[serde(tag="kind")]` PascalCase. Mirrored the real shape and fixed
  every fixture; round-trip test pins the exact strings for
  At/Every/Cron. Snapshot no longer fails on every real workspace.
- **F3 (HIGH) — snapshot write atomicity.** Each automation's
  work-item + routine + revision + mapping writes now commit in ONE
  immediate transaction on ONE connection (`create_in`/`append_revision_in`
  connection-scoped repository methods); mapping-row-exists skip keeps
  re-runs idempotent. Test: forced routine-write failure after the
  work-item insert leaves zero rows behind.
- **F4 (HIGH) — agent CronTool ungated post-enable.** The tool's typed
  refusal is unreachable (isanagent pinned), so the host seam withholds
  CronTool from the registry when canonical scheduling owns the
  workspace (`SharedInstanceHooks.suppress_agent_cron`,
  desktop_host build_instance computes the gate; stdio_host passes
  false mechanically). Negative tests: suppress on → no "cron" tool;
  default → registers as before. Accepted residual (sharpened in
  re-check round 2): an already-built instance survives a flag flip
  until rebuild, and through its still-registered CronTool it can still
  CREATE automations post-flip. Creation succeeds, but until the
  instance rebuilds the new automation can neither fire (the fire-time
  gate suppresses legacy firing once the flags are on) nor transfer
  (it has no mapping row) — it is stranded suppressed, and `schedule
  enable` now fails typed at its post-flag re-verify naming such a
  newcomer instead of stranding it silently.
- **F5 (HIGH) — paused automations resurrected as Active.** enabled=0
  automations now transfer to `RoutineStatus::Paused`; only Active
  routines materialize, so nothing resurrects, and a faithfully
  transferred paused row does not permanently block enable.
- **F6 (HIGH) — enable flow had zero production surface.** The daemon
  binary grows `schedule snapshot|enable|status` subcommands enforcing
  the D3 freeze order: snapshot → verify_enable_ready (typed-closed,
  naming unmapped/incompatible) → set_if_absent schedule_owner →
  set_if_absent control_plane_enabled → mark_retired (insert-only
  writes: first decision wins, conflicts error typed). All three
  refuse a workspace without an agent store. The bare `serve`
  invocation is unchanged.
- **F1b/TS-F6 (HIGH) — renderer gate was the sole arbiter.**
  `orchestration_reconcile` consults the scheduling authority before
  taking the state lock; canonical → empty claims (typed no-op) with
  bookkeeping live. A missing work.db answers legacy without opening
  the ledger — no per-tick materialization (the TS-F4 backend half).
- **F7/F8 (MEDIUM) — desktop driver vs the workspace lock; silent
  failures.** The driver now spawns only from the `work_store()`
  success path and holds a `Weak<WorkStore>`, stopping when the store
  is gone; every repository-open/tick/spawn failure logs
  `log::error!` naming the workspace.
- **F9 (MEDIUM) — fire-time gate failed open on ledger errors.** The
  gate resolves to `Option<bool>` plus a per-workspace last-known
  cache: on read error it suppresses iff last-known canonical (first
  read absent → legacy, preserving flag-off), and a missing work.db
  answers legacy without materializing one.
- **TS-F1/F3/F5 (renderer).** The silent fail-open catch now logs with
  context; the canonical early-return moved below hydrate +
  record_terminal so bookkeeping keeps running for a legacy session
  that is RUNNING at cutover (claim/dispatch stays gated; a
  per-workspace `schedulingSuppressed` store flag exposes the state to
  the UI); a malformed authority payload falls back to legacy-shaped
  semantics with a log instead of being trusted.
- **TS-F2 — zero tests.** `reconcile` is exported for tests and
  OrchestrationController.test.ts covers: canonical → bookkeeping runs,
  zero claim/dispatch calls; authority rejection → logged legacy
  fallback; canonical off → invocation sequence identical to the
  ungated flow (invocationCallOrder); malformed payload → legacy via
  the native guard.
- **LOWs.** Bridge authority-lookup errors release the lock; corrupt
  disposition strings fail typed and block enable; hex() writes into a
  pre-sized String. Accepted nit: `now_unix_seconds` stays duplicated
  across the two drivers (cross-lane dedupe rejected as churn).

### Re-check round 2 (adversarial re-check, CHANGES-REQUESTED: N1 HIGH, N2 MEDIUM, N3 LOW)

- **N1 (HIGH) — dual-run window between snapshot and enable/rollback.**
  The snapshot writes enabled automations as `Active` mirror routines
  BEFORE the flag flip, so in the undecided, crash-gap-before-enable,
  and rollback states the daemon bridge's restored unconditional legacy
  tick drove every Active routine — including the mirrors — while the
  desktop's CronActor still fired the legacy `cron_jobs` rows: every
  mapped Cron automation ran twice, violating invariant 2. Fix:
  mapping-aware legacy drives. The gated bridge's undecided/rollback
  tick now reads the v6 mapping store (same work.db) and materializes
  only Active routines with NO mapping row; the DECIDED canonical paths
  (daemon owner tick, desktop driver) still drive every Active routine.
  With zero mapping rows the filter is empty and the legacy tick is
  byte-for-byte the pre-cutover one (flag-off acceptance preserved). A
  read-only verification found no desktop-side dual-run: the desktop
  `SchedulerDriver::tick` idles unless `canonical_decided()`, so in the
  undecided state only the CronActor fires there. Tests: undecided +
  mapped Active + unmapped Active → only unmapped materializes;
  legacy-rollback the same; decided + owner=daemon → the mapped mirror
  materializes (no over-suppression); zero mapping rows → all Active
  materialize.
- **N2 (MEDIUM) — enable's verify→flag window and silent retire.**
  (a) `mark_retired` discarded the UPDATE's rows-affected count and
  silently no-oped on a missing mapping row; it now refuses typed
  (`TransferError::MappingMissing`) while an already-retired row stays
  an idempotent Ok. (b) `schedule enable` re-runs `verify_enable_ready`
  AFTER the insert-only flag writes; if an agent instance created an
  automation through the still-registered CronTool in the verify→flag
  window, the re-verify fails typed (`EnableBlocked`) naming the
  newcomer. Semantics of that state: the flags stay recorded (insert-
  only, first decision wins — the workspace is decided), the newcomer
  can neither fire nor transfer until the instance rebuilds/snapshot
  runs, and the typed error plus stderr guidance point the operator at
  the resolution: re-run `schedule snapshot` (idempotent), then
  `schedule enable` (equal-value flag writes accepted, retirement
  completes). Tests: mark_retired on a missing mapping row → typed
  error; newcomer after the flag writes → typed error naming it, flags
  unchanged, nothing half-retired.
- **N3 (LOW) — clippy.** `cargo clippy -p altai-control-plane
  --all-targets -- -D warnings` is now clean. The 4 pre-existing
  `altai-core` test warnings (legacy_import.rs, palette.rs) are NOT
  introduced by this packet and remain, noted as follow-up.
