- Protocol crate: two command payloads (`CreateWorkItemCommand`,
  `TransitionWorkItemCommand`), two outcome arms

- Control-plane crate: `ProtocolDispatcher` gains an optional

  `work_graph` derives from either work-graph bit. `transport.rs`,
  `main.rs`, and the desktop host pass the new repository through.

- TS package: mirrored command/outcome unions + payload interfaces +

## The eight-step command pattern

1. **Version gate** — request major version must match, else typed
   `PolicyDenied` (existing first gate, unchanged).
2. **Capability check** — the deployment advertises `work_graph`.
3. **Wiring check** — the work-item repository is attached; otherwise
   typed `PolicyDenied` naming the capability (same shape as
   activity/replay today).
4. **Input validation** — canonical vocabulary arrives via serde; typed
   IDs must carry their own `type` discriminant (`InvalidId` otherwise);
   title/description within named byte caps (`PayloadTooLarge`).
5. **Scope resolution** — the project must exist (`NotFound`), the work
   item is addressed within its project (`get_in_project`).
6. **Invariant check** — duplicate create → `Conflict`; transition with a
   non-current revision → `StaleRevision`.
7. **Transactional persist** — INSERT at `Revision::INITIAL` or optimistic
   UPDATE with `revision.next()` in the canonical repository.
8. **Attributed projection + typed outcome** — append the ActivityEvent
   and ControlEvent with the framed actor, then return the read-your-write
   `WorkItem` in the envelope. A post-commit event-append failure surfaces
   as typed `InternalError` (never silent).

## Required negative tests

- Un-wired dispatcher → `PolicyDenied` naming `work_graph`, identical on
  both transports.
- Stale `expected_revision` → `StaleRevision` (never an update).
- Unknown `work_item_id` / unknown `project_id` → `NotFound`.
- Duplicate `work_item_id` → `Conflict`.
- Oversized title → `PayloadTooLarge`.
- Typed ID with a foreign `type` discriminant → `InvalidId`.
- Version major mismatch still wins before any mutation (no write).

## Compatibility and deletion effects

   full mutation surface (work-item store + both audit stores), so no
   deployment advertises what it cannot attribute.

   resolved: `concurrent_transitions_from_the_same_revision_admit_exactly_one`

   `WorkItemTransitioned`, exactly one typed `StaleRevision`, final
   revision 1, and a final status that is exactly one of the contenders.
